Nginx Reverse Proxy

Publica un servicio interno en el puerto 8080.

$ sudo apt install nginx -y
$ sudo nano /etc/nginx/sites-available/miapp

server {
  listen 80;
  server_name miapp.mexweb.me;

  location / {
    proxy_pass http://127.0.0.1:8080;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
  }
}

$ sudo ln -s /etc/nginx/sites-available/miapp /etc/nginx/sites-enabled/
$ sudo nginx -t && sudo systemctl reload nginx

server {

me dice que spotify rechazo la conexion https://spotify.mexweb.me/app/#/login El error "refused to connect" (conexión rechazada) que estás viendo se debe a una medida de seguridad implementada en Navidrome (y en la mayoría de las aplicaciones web modernas) llamada X-Frame-Options y Políticas de Seguridad de Contenido (CSP). Por defecto, Navidrome está configurado para bloquear que otros sitios web lo incrusten dentro de un iframe para evitar ataques de Clickjacking. Para que puedas incrustar tu servidor Navidrome en tu página de MexWeb, necesitas modificar la configuración de Navidrome o de tu proxy inverso (Nginx) para decirle: "Oye, sí permito que mexweb.me incruste mi reproductor". Aquí tienes las soluciones exactas: Solución 1: Modificar la configuración de Navidrome (Si usas navidrome.toml o Docker) Si tu servidor Navidrome es reciente, no soporta la desactivación de estas cabeceras directamente desde su archivo de configuración interno, ya que asume que lo pones detrás de un proxy (Nginx, Caddy o Cloudflare Tunnel) que maneja las cabeceras. Pasa a la Solución 2 si Navidrome está detrás de Nginx (que es lo más seguro). Solución 2: Modificar Nginx (La forma correcta) Si estás usando Nginx como Proxy Inverso para apuntar spotify.mexweb.me al puerto interno de Navidrome (4533), Nginx es quien está enviando la cabecera restrictiva. Conéctate por SSH a tu servidor Linux (192.168.1.104). Abre la configuración de tu sitio de Navidrome: Bash sudo nano /etc/nginx/sites-available/navidrome (Cambia "navidrome" por el nombre de tu archivo de configuración).
